Mon rôle

Lead Product Designer & Product Manager

Responsabilité produit de bout en bout : vision, roadmap, priorisation, specs, design system, delivery.

J'encadre une équipe de 5 développeurs (backend, front web, Flutter, tech lead) et 1 product designer, en pilotage direct avec le CEO et le CTO. Je porte les arbitrages face aux clients (Ewigo, Dubreuil, CentraCar).

  • Design — design system complet (tokens, composants, motion), 17-shots template, écrans de capture, paywall, onboarding.
  • Product — roadmap trimestrielle, +20 cycles Linear, 300+ issues, Definition of Done formalisée, sprint planning hebdo.
  • Stratégie — modèle de monétisation self-service (IAP + RevenueCat + Stripe), architecture multi-org, pricing B2B/B2C.

Ce que je n'ai pas fait : le code (Flutter / NestJS), l'infra AWS, les négociations contractuelles clients (Sales / CEO).

Trois décisions

Les arbitrages qui ont façonné le produit

  1. 01

    Crédits org-level plutôt que user-level

    Premier MVP : crédits attachés à l'utilisateur. Problème détecté en discovery groupe Dubreuil — un vendeur qui part emporte ses crédits. J'ai imposé une migration vers un ledger DynamoDB org-scoped, FIFO, expiration glissante 12 mois.

    Coût : 3 semaines de refacto backend. Bénéfice : un modèle viable pour les groupes multi-sites — qui représentent 80 % du revenu cible.

  2. 02

    Reporter le haptic feedback, livrer l'invitation in-app

    À deux semaines du Split Autoya, deux features candidates restaient au sprint. Le haptic feedback était plus séduisant côté démo. L'invitation in-app fermait la boucle d'onboarding self-service — sans elle, pas de viralité B2B.

    J'ai tranché pour l'invitation, reporté le haptic au backlog. Décision impopulaire côté équipe, alignée sur la stratégie.

  3. 03

    IAP consumables uniquement en Phase 1

    La contrainte Apple « un seul abonnement actif par Apple ID » bloquait les groupes multi-comptes. Plutôt que d'attendre une architecture parfaite (subscription groups + org switching), j'ai cadré une Phase 1 : packs de crédits consommables via IAP, abonnements via Stripe web.

    Délai au lancement : −6 semaines. Le modèle est imparfait, assumé, documenté dans la roadmap Phase 2.
