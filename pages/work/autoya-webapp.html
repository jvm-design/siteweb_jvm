Mon rôle

Lead Product Designer & Product Manager

Responsabilité produit de bout en bout sur la web app : vision, roadmap, specs, design system, delivery — seul designer/Product Manager sur le projet.

Je travaille en binôme avec le CTO, en pilotage direct avec le CEO. Je porte le discovery automobile, le cadrage de la solution SaaS, le positionnement B2B et le modèle de monétisation par crédits.

  • Design — design system monochrome documenté (tokens CSS, 30+ règles, shadcn/ui + Radix, Motion), specs UX détaillées sur dashboard, studio, settings, auth, onboarding.
  • Product — 15+ documents de spec, flows end-to-end (auth → onboarding → production → DMS), priorisation backlog, critères d'acceptance, +300 issues sur +20 cycles Linear.
  • Stratégie — modèle multi-tenant orgs + groupes, monétisation crédits + Stripe, ciblage réseaux multi-sites.

Ce que je n'ai pas fait : le code (React 19 / TypeScript / NestJS), l'infra AWS, les pipelines IA (CTO + équipe back).

Trois décisions

Les arbitrages qui ont façonné la plateforme

  1. 01

    Feature-Sliced Design comme socle d'architecture

    Premier cadrage : structure front classique par layer (components, pages, hooks). J'ai imposé Feature-Sliced Design pour isoler chaque domaine métier — auth, studio, workflows, billing, orgs — et préserver la vélocité quand l'équipe grandit.

    Coût : courbe d'apprentissage initiale, 30+ règles d'architecture à documenter. Bénéfice : nouvelles features ajoutées sans dette transversale, pas de refacto majeure en 12 mois.

  2. 02

    Cutout Studio canvas-based plutôt qu'un upload "fire and forget"

    Premier MVP envisagé : pipeline batch — upload, traitement IA asynchrone, résultat livré. Discovery concessions : les vendeurs veulent du contrôle créatif fin (recadrage, fond, retouche) sur chaque véhicule.

    J'ai cadré un studio canvas interactif avec snap magnétique, templates de fond, génération IA en un clic. UX d'édition créative grand public posée sur un outil B2B — devenu l'argument différenciant face aux solutions concurrentes.

  3. 03

    Multi-tenant orgs + groupes dès le MVP

    Premier scope : orgs simples, groupes "plus tard". Mais les réseaux multi-sites (Dubreuil-like) représentent 80 % du revenu cible. Bolt-on a posteriori = migration douloureuse pour les early adopters.

    J'ai imposé la structure orgs + groupes en phase 1 — vue réseau, crédits partagés, allocation par filiale. Coût : 3 semaines de design + back supplémentaires. Bénéfice : commercialisation immédiate sur les groupes, pas de migration tardive.
